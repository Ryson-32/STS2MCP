# 证据与验证

## 先确认事实再下结论

- 先读取当前代码、配置、文档、日志和测试，再判断问题。
- 版本、规则、价格、远端服务和生产状态等可能变化的事实，使用当前可复查来源核验。
- 外部 AI、旧报告、截图和历史记录是线索，不是当前代码或运行状态的事实源；每条发现都要回到当前证据判断。

## 可复用文献进入全局主库

- 在调研、设计、实现、审查或写作中发现或下载的文献，只要经初步判断可能服务于其它项目、通用方法、领域背景或未来工作，就应在核对题录身份和重复项后收入用户级 Zotero 主库；不以已经被当前项目引用为前提。
- 检索命中或 PDF 下载成功不等于完成归档。当前主机有可写的 Zotero MCP 或正式导入入口时，应在任务结束前明确写入；用途暂不明确的进入 `00-Inbox`，用途明确的进入对应项目或共享主题 Collection。付费墙或仅有摘要不妨碍先收入题录并标注访问状态。
- 上述归档规则是用户对“经身份核验和去重后写入用户级 Zotero 主库”的限定持续授权；文献检索或下载请求默认包含这一步，无需另问。用户本轮明确要求只读、禁止入库或禁止外部变更时停止；该授权也不涵盖其它外部写入、项目引用或本地文件合同。
- 明确无关、重复、身份无法核验或明显不可靠的来源不入库。无法写入时，在最终汇报中列出题名或 DOI 及原因，不把下载成功说成已经入库。收入全局主库不自动改变当前项目的 `.bib`、引用键、证据映射或本地文件合同；这些仍由项目规范管理。

## 不混淆证据层级

以下结论彼此不能自动推出：

1. 已配置或源码存在。
2. dry run、语法或静态检查通过。
3. 文件、构建或导出已生成。
4. 自动测试通过。
5. 真实运行、目标渲染器或远端服务已验证。
6. 已部署、发布或用户验收。

只报告实际完成的层级。UI 看起来正常、配置文本存在或命令退出码为零，不能代替真实请求、数据、页面或服务证据。

## 风险相称的检查

- 文档和规范：定向 diff、链接、旧引用、格式和敏感信息检查。
- 代码和合同：最小相关测试，再根据影响扩大到类型、构建、集成或回归检查。
- 数据和生成物：核对输入身份、派生关系、结构、关键不变量和实际输出。
- 远端或生产：记录目标、时间、命令、状态、回滚入口以及未验证项。
- 视觉交付：文件存在、结构检查、源对象检查和目标载体逐页/逐图检查分别报告。

## 零结果不是自动的“全部正常”

当结论依赖“没有命中、没有调用、没有泄露、没有剩余文件”时：

1. 先用同一命令搜索一个已知存在的对象，证明扫描链能够命中。
2. 检查生产命令的退出状态，不让 `head`、`wc` 或错误重定向掩盖失败。
3. 说明扫描范围、排除项和未覆盖的历史、编码或远端位置。
4. 从与目标受众相同的权限和网络位置验证可见性。

“跟踪文本未命中，历史未扫描”是有效结论；没有覆盖说明的“仓库完全干净”不是。

## 最终交接

列出实际修改、运行过的命令及结果、跳过或失败项、未覆盖风险，以及 commit、push、部署、发布或 PR 是否真实发生。不得把计划写成已完成。
