# 安全高效工作流

本规范是任务开始、恢复和范围切换时使用的短核心合同；具体工程、证据、授权或领域要求由直接命中的 owner 管理。

## 按需完整加载

- 先按入口索引选择当前任务直接命中的规则文件，不因文件之间互相链接而做传递式全量加载。
- 每次工具调用只读取一个选中的规则文件。输出被截断时从下一未读位置继续，直到 EOF；未完整读取的文件不算已加载。
- 同一工作上下文内已经完整读取、且文件与适用事实均未变化的规则可以复用；范围、版本或输入变化时重新选择并读取。

## 工作顺序

1. **理解**：读取当前任务、代码、配置、文档、日志和 Git 状态，区分事实与推测。
2. **定位**：已知文件、符号、字段、错误文本或配置键时先做精确搜索；需要探索未知 owner、关系、调用链或语义近似时优先使用可用的语义检索，再回到当前文件核实。
3. **规划**：明确目标、共享状态、验证、停止条件和可恢复边界；只拆分能独立判断结果的逻辑单元。
4. **修改**：小步编辑真实 owner，保护用户、其它 AI 和其它设备留下的现场。
5. **验证**：先运行能推翻本次改动的最小相关检查，再按实际影响扩大；记录失败、跳过和证据层级。
6. **交付**：简要说明实际改动、验证、外部动作和剩余阻塞，不用过程数量代替结果。

## 共享状态与恢复

- 互不依赖且不争用可变状态的读取、检索、静态分析和测试可以并行。同一共享 checkout 的写入和同一组共享 Git 动作同一时间只由一个 writer 串行执行；同一外部可变状态也由一个 owner 串行操作。
- 彼此隔离的 worktree 可以并行实现候选，潜在文件重叠不要求派发前切分精确 ownership；真实依赖约束主会话的最终集成顺序，主会话负责比较候选、解决冲突和执行共享验证与 push。
- 发现脏改动、ahead/behind、活动任务或未知生成物时先保留并识别来源，不回滚、不覆盖、不顺手纳入提交。
- 长任务建立可恢复检查点；失败后从最近已验证边界继续，不重复执行外部副作用。为节省时间而跳过的检查必须说明影响。
- 使用内置或用户浏览器时，复用仍有用途的本轮标签页，关闭本轮新开且已无用途的标签页，不打断进行中的工作。

## 精确提交

提交前查看状态、diff 和暂存内容，只包含当前逻辑单元。跨模块改动按可验证边界拆分；是否 push 由项目规则和当前授权决定。
