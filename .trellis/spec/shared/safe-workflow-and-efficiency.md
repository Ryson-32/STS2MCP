# 安全高效工作流

## 适用范围

本规范适用于任何任务，包括简单任务和只读任务；开始工作时必须读取并遵循。

## 规范加载必须完整

- 先按入口索引选择本任务命中的规范；每次工具调用只读取一个规范文件，不把多个长规范拼接到同一输出中。
- 工具报告输出被截断时，从下一未读位置按行段继续读取，直到确认到达文件末尾（EOF）。只有完整读到 EOF 的规范才算已加载。
- 任一命中规范尚未完整读取时，不得把截断内容当作完整合同，也不得据此开始规划、修改、验证、提交或外部操作。

## 标准顺序

1. **理解**：读取当前代码、配置、文档、日志、任务和 Git 状态，区分事实与推测。
2. **规划**：把目标拆成可独立验证的逻辑单元，明确风险、ownership、验证和停止条件。
3. **定位**：优先语义检索；不可用时用精确文件或文本搜索，不从模糊目录猜入口。
4. **修改**：小步编辑现有拥有者，随时保护用户、其它 AI 和其它设备留下的现场。
5. **验证**：先运行最相关的小范围检查，再按影响扩大；保存实际命令、结果和未覆盖项。
6. **汇报**：说明真实完成层级、提交与外部动作，不把计划、配置存在或生成成功写成验收通过。

## 并行与 ownership

- 互不依赖的读取、搜索、日志检查、静态分析和测试可以并行。
- 同一共享 checkout 的写入和同一组共享 Git 动作同一时间只由一个 writer 串行执行；迁移、集成、push、发布、部署、重启和生产数据操作也按各自真实共享状态串行。
- 彼此隔离的 worktree 可以并行实现候选，潜在文件重叠不要求派发前切分精确 ownership；真实依赖约束主会话的最终集成顺序，主会话负责比较候选、解决冲突和执行共享验证与 push。
- 发现脏改动、ahead/behind、活动任务或未知生成物时先保留并识别来源，不回滚、不覆盖、不顺手纳入提交。

## 效率不降低质量

- 复用已经核验的事实、脚本和缓存，但在版本、远端状态或输入已经变化时重新验证。
- 使用内置或用户浏览器时，按后续用途复用或关闭本轮新开的标签页；已无后续用途的及时关闭，但不为清理打断仍在进行的工作。
- 长任务建立可恢复检查点；失败后从最近已验证边界继续，不重复执行外部副作用。
- 大范围工作分批推进，每批通过相同质量门后再扩大，单个失败对象不应污染其它对象。
- 为节省时间而跳过的检查必须写明影响；不能把“预计没问题”改写为“已验证”。

## 精确提交

提交前查看状态、diff 和暂存内容，只包含当前逻辑单元。跨模块改动按可验证边界拆分提交；是否 push 由项目规则和当前授权决定。
