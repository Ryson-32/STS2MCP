# 敏感信息与脱敏

## 不得进入 Git 的内容

- API key、token、密码、私钥、恢复码、OAuth secret 和完整认证文件。
- 完整请求/响应体、原始生产日志、数据库 dump、邮件正文和可识别个人的信息。
- 用户名、主机名、公网 IP、服务器清单、私人邮箱、账号状态和不必要的本机绝对路径。
- 用户级客户端登录、trust、provider、MCP、通知和审批状态。

私有仓库也必须遵守；“不是公开仓库”不等于可以长期存放凭据。

## 正确的证据保留方式

- 只保留支持结论所需的最小脱敏摘要：来源、时间范围、组件、操作、状态、错误类别和无敏感性的公开标识。
- 使用占位符、汇总数量、短且无秘密的错误摘要和仓库相对路径。
- 原始证据留在拥有它的本地或远端系统，并通过安全入口重新核验。
- 配置文件只保存环境变量名称或密钥位置，不保存真实值。

## 提交与发布前

1. 查看准确的 staged diff 和待推送提交，不依赖宽泛状态摘要。
2. 执行适合仓库的 secret-pattern 扫描，并确认扫描链能命中已知测试样例。
3. 检查新增日志、截图、导出文件、环境配置和历史补丁是否包含私人信息。
4. 公共仓库额外按匿名访问者的视角核验可见内容。

发现疑似泄露时停止 push，记录最小证据并在外部安全系统轮换凭据。是否改写已共享 Git 历史需要单独方案和明确授权，不能用普通清理顺手处理。
