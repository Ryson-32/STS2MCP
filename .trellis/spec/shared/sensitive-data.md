# 敏感信息与凭据

## 真实凭据不得进入 Git

- API key、token、密码、私钥、恢复码、OAuth secret、session cookie、服务账号密钥和完整认证文件不得写入仓库、任务记录、补丁或日志样例。
- 配置只保存环境变量名、安全入口或无真实值的占位符。私有仓库也必须遵守；“不是公开仓库”不等于可以长期保存凭据。
- 日志、请求、响应、导出或配置可能夹带凭据时，提交前必须检查实际内容；发现真实值就停止暂存和 push，并在拥有凭据的外部系统中处理轮换。

## 非凭据本机材料与元数据

- 原始日志、请求/响应、数据库导出、邮件或个人信息、用户名、主机名、IP、设备清单、账号状态、本机路径和客户端状态本身不构成本共享规则的跨项目 Git 禁令。
- 这些非凭据材料是否可以跟踪、推送、共享或公开，由消费仓库的 `AGENTS.md`、项目 spec、受众与用户当前指令明确管理；共享规则不替代仓库自己的证据、隐私和发布合同。
- 项目要求脱敏或只保留摘要时，使用支持结论所需的字段、汇总数量、无秘密错误类别和仓库相对路径。项目允许保留原件时，仍须先确认其中没有真实凭据，并按其明确的访问与发布范围处理。

## 提交与发布前

1. 查看准确的 staged diff 和待推送提交，不依赖宽泛状态摘要。
2. 执行适合仓库的 secret-pattern 扫描，并先用已知测试样例确认扫描链能够命中。
3. 检查新增日志、截图、导出、环境配置和历史补丁是否夹带真实凭据；非凭据内容按当前仓库合同判断。
4. 公共仓库额外从匿名访问者视角核验实际可见内容。

发现疑似凭据泄露时停止 push，记录不含真实值的最小证据并在外部安全系统轮换。是否改写已共享 Git 历史需要单独方案和明确授权，不能用普通清理顺手处理。
