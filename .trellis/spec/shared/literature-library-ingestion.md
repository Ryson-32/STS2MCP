# 文献主库归档与分类

## 可复用文献进入全局主库

- 在调研、设计、实现、审查或写作中发现或下载的文献，只要经初步判断可能服务于其它项目、通用方法、领域背景或未来工作，就应在核对题录身份和重复项后收入用户级 Zotero 主库；不以已经被当前项目引用为前提。
- 检索命中或 PDF 下载成功不等于完成归档。当前主机有可写的 Zotero MCP 或正式导入入口时，应在任务结束前明确写入；用途暂不明确的进入 `00-Inbox`，用途明确的进入对应项目或共享主题 Collection。付费墙或仅有摘要不妨碍先收入题录并标注访问状态。
- 上述归档规则是用户对“经身份核验和去重后写入用户级 Zotero 主库”的限定持续授权；文献检索或下载请求默认包含这一步，无需另问。用户本轮明确要求只读、禁止入库或禁止外部变更时停止；该授权也不涵盖其它外部写入、项目引用或本地文件合同。
- 明确无关、重复、身份无法核验或明显不可靠的来源不入库。无法写入时，在最终汇报中列出题名或 DOI 及原因，不把下载成功说成已经入库。收入全局主库不自动改变当前项目的 `.bib`、引用键、证据映射或本地文件合同；这些仍由项目规范管理。

## 文献入库的主动分类与标签

### 入库前检查

- 写入前读取主库中的现有题录与附件、Collection 树、标签词表和同义词；使用 DOI、ISBN、附件 hash、规范化题名等当前入口可用的标识检查题录或 PDF 重复项，不能先写入再凭印象补救。
- 分类证据从已核验题录元数据到摘要、已核验全文逐级增强。文件名、当前仓库或工作目录只能作为待核验线索，不能单独证明项目归属、内容主题或技术方法。

### 项目与内容双轴 Collection

- 项目 Collection 回答“这篇文献服务于哪个项目”，内容或方法 Collection 回答“这篇文献讲什么、采用什么宽方法”；两种归属彼此独立，同一条目可以同时进入一个或多个项目 Collection 和一个或多个内容或方法 Collection，不因此复制条目或附件。
- 项目归属必须有当前项目引用、已记录的任务用途、用户确认或其它可追溯证据。无法确认时保留在 `00-Inbox`，不得根据当前仓库、工作目录或名称相似度猜测；这不妨碍完成已有证据支持的内容分类。
- 内容分类应在入库时主动完成，优先使用最准确的现有宽主题或方法 Collection。没有准确现有分类、且新分类代表稳定可复用的宽领域时，可以新建；现有分类会歪曲文献含义时不得勉强塞入。

### Collection 与标签的边界

- Collection 用于有证据的真实项目，或稳定、可复用的宽主题与方法领域；标签用于可交叉组合的细粒度现象、阶段、方法、研究类型、用途角色和处理状态。不得为单篇文献的每个关键词新建 Collection。
- 新建 Collection 或标签前检查现有词表，统一同义词、拼写、大小写和语言，避免同一概念出现多套名称。普通入库不得顺手删除、合并、重命名或重构旧分类；历史整理必须另设明确授权且可回退的任务。
- 默认标签采用一致的斜杠前缀和规范化小写英文词形，例如 `phenomenon/*`、`stage/*`、`method/*`、`study/*`、`role/*`、`status/*`。项目可以用明确合同扩展或替代默认词表，但同一库内应保持单一词表并避免同义重复。
- `phenomenon/*`、`stage/*`、`method/*`、`study/*`、`role/*` 等内容或用途标签只能依据已核验题名与题录、摘要或全文添加，不把未读全文时的推测写成确定事实。`status/*` 只记录实际工作流状态，不表示文献内容；内容证据不足但值得后续判断时，不添加推测的内容标签，而是添加 `status/tag-review` 或项目约定的等价复核标签，并保留 `00-Inbox`。
- 不把作者、年份、期刊、是否有附件等已有结构化字段复制成标签，也不批量照搬出版商关键词。

### 写后回读与授权边界

- 写入后重新读取题录身份、附件、Collection 归属和标签。出现写入失败、意外重复、覆盖、错误归属或回读不一致时，对当前条目失败关闭并停止继续写入。
- 用户明确要求“只讨论”“只读”、禁止入库或禁止外部写入时，不得创建或修改条目、Collection、标签或保存的搜索。分类授权不自动扩大到项目 `.bib`、正文引用、全文下载、删除旧条目、永久合并或其它外部动作。
