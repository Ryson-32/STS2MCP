# 跨平台验证

## 共同原则

- Mac 和 Windows 复用相同的业务合同、数据格式和主要入口；平台适配不得悄悄改变另一端已验证的行为。
- 共享规则和代码使用相对路径、配置入口和占位符，不写死用户名、盘符、包管理器前缀或单机安装目录。
- 只声明实际验证的平台；另一端未实测时明确入口、已知差异和待补测项。
- 不为未验证的平台提前增加复杂兼容层，也不因当前端能运行就声称双端兼容。

## 分开三种验证合同

| 对象 | 正确检查 |
|---|---|
| 文件来源和不可变产物 | 精确哈希、来源提交和文件身份 |
| 跨架构数值或行为等价 | 形状、类型、不变量和明确容差/行为断言 |
| 工具是否可用 | 运行项目真实入口或平台支持的发现机制 |

不能因为浮点库在不同 CPU 上存在末位差异，就放宽所有源文件哈希；也不能因为某个应用不在非登录 shell 的 `PATH` 中，就认定它没有安装。

## 常见差异

检查路径分隔符、大小写、换行、编码、shell 语法、权限、字体、渲染器、压缩库、桌面应用发现方式和 CPU 数值库。平台专用命令应明确标注运行环境，不把 PowerShell、zsh/bash 和 CMD 语法混写成一个命令。

## Windows、WSL 与挂载文件系统

WSL 访问自身 Linux 文件系统与通过 DrvFS 访问 NTFS 路径时，权限和文件类型语义可能不同。验证前先确认数据实际位于哪类文件系统、使用什么挂载选项，以及最终由 Windows、WSL 还是两者共同消费；不能只根据挂载路径或一组 mode bits 推断权限合同。

| 验证维度 | 必须区分的事实 |
|---|---|
| 内容完整性 | 相对路径集合、文件类型、逻辑字节数、内容哈希或校验和，以及任务声明的格式/业务不变量 |
| Linux 权限 | WSL 原生文件系统中的 POSIX mode bits，或 DrvFS 挂载是否启用并持久化相应元数据 |
| Windows 权限 | NTFS 安全描述符和实际 Windows 身份的 ACL；它不等价于 WSL 中显示的 mode bits |
| 链接与特殊语义 | 符号链接、硬链接、可执行位、大小写和特殊文件是否被目标文件系统及消费入口真实保留 |

- 内容验收使用实际访问路径和消费身份：Windows 程序访问 NTFS/DrvFS 目标时，从相应 Windows 身份验证 ACL 和可读写性；Windows 程序通过 `\\wsl$` 访问 WSL 原生文件系统时，从该发行版的默认 WSL 用户验证；WSL 工具直接访问时，从实际 Linux 进程身份验证。多个入口都会消费时，分别检查。
- DrvFS/NTFS 无法按当前挂载合同表达 Linux 权限时，`rsync` 的权限字段差异不等于文件缺失。只有在输出已证明差异仅限权限、权限本身不是交付要求且没有访问错误后，才可用 `--no-perms` 排除权限比较；这只改变权限处理，不自动证明内容一致。
- 忽略权限比较后仍必须验证路径集合、文件数量、逻辑总字节和合同要求的格式/业务不变量。需要证明源端与目标端内容相同时，使用独立哈希，或在保留其它传输选项的同时运行 `rsync --checksum --dry-run --itemize-changes --no-perms`，并要求内容变更列表为空；普通 dry run 默认只按大小和修改时间快速判断，不能代替内容校验。任何 unreadable、skipped、I/O error、缺失或意外额外文件都属于内容失败。
- 硬链接关系属于交付合同时，除内容哈希外还要用目标平台支持的文件身份检查证明目标共享同一文件；相同内容不能代替相同文件身份。
- 需要 Linux 可执行位、所有权、符号链接或特殊文件语义时，不把普通 DrvFS/NTFS 复制当作等价交付；改用能保留这些语义的 WSL 原生文件系统或明确的归档/镜像合同，并在解包后复验。
- 不能确认挂载语义、无法把差异限定为权限、不同身份得到的内容清单冲突，或内容不变量不一致时，停止完成声明并保留现场；报告未验证维度和下一条最小复验命令。

## 验证要求

- 使用相同仓库提交和输入合同运行各端入口。
- 记录操作系统、关键工具版本、命令和输出身份，但机器专属细节放在 ignored 本地记录中。
- 平台差异只影响发现或环境准备时，不修改业务或科学行为来迎合某一端。
- 无法实测另一端时，在交接中写明由另一端执行的最小复验步骤。
