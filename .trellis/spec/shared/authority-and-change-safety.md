# 权限与变更安全

## 授权不自动扩大

- 用户对当前仓库、任务或实现的授权，不自动包含其它仓库、用户级配置、生产环境或外部系统。
- 创建 Trellis 任务、计划文件、临时 fixture 或检查记录只是过程元数据，不扩大实施权限。
- 已明确授权实施且最终范围没有扩大时，不因流程形式再次索要批准；目标、风险、外部影响或产品决定改变时重新确认。
- 对可验证为私有的仓库，用户已授权实施且当前指令或更高优先级项目规则未限定只读、仅本地、禁止提交或禁止 push 时，完成一个验证通过的逻辑单元默认包括模块化 commit，以及向已验证 tracking remote/branch 的普通 push；无需为这两个默认步骤重复索要形式批准。
- 对公开仓库，修改授权不自动包含 push；是否 commit/push 必须结合当前用户指令、项目规则、分支/PR 合同和公开信息风险逐案判断。对外提交前还要按[敏感信息](sensitive-data.md)从匿名访问者视角检查私人路径、身份、内部状态、凭据和不应公开的 Trellis/runtime 内容。
- 当前指令和项目规则可以收紧私有仓库默认值，也可以明确授予公开仓库普通 push；无法验证仓库可见性、remote、branch 或权限时采用保守停止，不猜测为私有仓库，也不向第三方 upstream、未知 remote 或非授权分支 push。
- 普通 push 的授权不自动包含 PR、tag、release、部署、生产变更、远端设置或用户级配置修改。

## 高风险边界

以下操作执行前必须核对目标、影响、恢复入口和有效授权范围；已由上节持续授权覆盖的普通 commit/push 不重复索要形式批准：

- 大量删除或移动、历史改写、强制覆盖、不可恢复清理。
- 公共 API 破坏性变更、重依赖升级、认证授权修改、数据库迁移。
- 普通 push 按上节私有/公开仓库边界判断；force push、tag、PR、发布、部署、生产配置或远端仓库设置变更必须分别获得相应授权。
- 用户级客户端配置、系统级规则、账号、密钥、登录和审批状态修改。

普通本地实现、测试和可删除临时 fixture 不因“谨慎”被升级为额外许可门，但仍须限制在当前范围内。

## 破坏性操作

1. 用只读命令解析准确目标，不对宽泛目录、未展开变量或未知通配符直接操作。
2. 优先可恢复操作；必要时先备份当前内容和身份信息。
3. 先在单个代表对象或 dry run 中验证，再扩大范围。
4. 操作后核对实际删除、迁移或覆盖的对象，并说明能否恢复。

不得把 `$HOME`、`~`、磁盘根、Workspace 根或仓库根作为未经精确解析的递归删除目标。

## 失败关闭

认证失败、仓库可见性或 push 目标无法验证、远端分叉不满足[双端 Git 协作](cross-device-git.md)的谨慎收敛条件、候选再次变化、验证失败或作用域不明时停止当前对象。不要用 force、reset、宽泛暂存或跳过检查来制造成功；其它相互独立且状态明确的对象可以继续并单独报告。
