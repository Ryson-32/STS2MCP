# VPS 与远端操作

## 适用范围与归属

涉及 VPS、SSH 或其它远端操作时，开始操作前必须读取本规范，包括只读排查、状态与版本发现、临时验证、配置、部署和故障恢复。项目指定资产库、连接入口及业务验收合同；本文件维护跨项目操作底线。文字规则提供执行与复核依据，不能代替工具约束或证明 AI 每次都会正确执行。

授权与变更范围遵循[权限与变更安全](authority-and-change-safety.md)，命令引用和跨 shell 传输遵循[Shell 与命令可移植性](shell-and-command-portability.md)，凭据处理遵循[敏感信息](sensitive-data.md)，完成声明遵循[证据与验证](evidence-and-verification.md)。

## 操作前确认目标

- 先读取项目指定的资产记录、当前用途、关键服务、历史故障及操作合同，再用最小只读查询核验目标身份、实际系统、服务和当前版本。旧记录与当前状态不符时先解释差异，不把历史结论直接当成执行依据。
- 使用项目登记的 SSH 或管理入口，从受管配置解析目标、端口、用户和密钥；不在临时命令中猜测或另抄连接资料。连接展示与 dry run 只能证明解析结果，实际连接还须核对远端身份和预期响应。
- 复杂脚本通过已验证的 stdin 或脚本文件入口传输，并显式选择远端解释器；平台不支持该传输方式时按 Shell 规范使用其专用入口，不经过多层未知默认 shell 拼接。
- 操作前明确预期结果、影响范围和停止条件。需要临时进程、文件、会话或监听时，同时确定其远端身份与清理方法。

## 安全发现程序与版本

- 优先使用包元数据、已有管理 API、服务管理器及进程元数据识别程序。Linux 可读取确定目标的 `/proc/<pid>/exe`；服务启动参数可能带凭据，只提取必要的安全字段。
- 只有程序身份及版本查询语法均已确认后，才执行它的文档化只读接口。`version`、`--version`、`-v` 不是通用只读协议；未知程序可能忽略参数并启动业务服务。
- 禁止遍历 `/proc/[0-9]*/exe` 后逐个执行候选程序来筛选名称或版本。无法确认接口时返回“版本未确定”，继续使用元数据或已知 API，不试运行全部候选。

## 远端执行与清理

- 临时执行必须有远端超时和可识别的 PID、进程组或独立服务单元；按工具能力记录足以复核的启动身份，不能仅凭可能复用的 PID 或宽泛进程名删除对象。
- 本地 SSH 返回、超时或被终止，不证明远端子进程已退出。成功、失败和中断后均须回读本次临时进程、会话、文件与新增监听；清理已无用途的临时资源，并确认业务原有监听和服务未被误伤。明确获准保留的产物或长期服务按项目合同核验并记录。
- 超时或断连后，通过登记入口重新核对执行边界，再决定清理或恢复；结果未知时不盲目重跑有副作用的命令。只处置本次确认归属的对象，不宽泛 kill 同名业务服务。
- 修正脚本后还要核对旧尝试遗留的进程、会话和端口。无法重连、身份不能确认或清理失败时，报告“结果未确认”或“清理未完成”，保留安全的定位依据和下一步，不将新测试通过当作旧副作用消失的证据。

## 变更、恢复与业务验证

- 对会覆盖配置、迁移数据或重建服务的操作，按项目合同先保存必要的当前配置、版本及可恢复数据，明确恢复入口和触发条件；需要备份时核对备份实际存在、可读取并符合该操作的恢复要求，不能只记录备份命令成功。
- 先在代表对象或隔离环境验证，再按已授权范围推广。验证可疑命令是否意外启动服务时，使用隔离网络或测试机，不在生产中重现开放代理或异常大流量。
- 操作后检查真实业务请求、关键数据和相关日志；服务进程存在、端口正在监听、TCP 可连接、协议请求成功与业务可用分别陈述。监听地址包括通配地址也不证明公网可达，采集失败不证明端口关闭。
- 验证失败时按项目恢复合同处理，复查恢复后的实际服务。恢复动作退出成功不等于业务恢复，未覆盖的平台或网络位置明确保留为未验证。

## 操作记录与资产更新

- 为实际远端操作保留可关联的开始与结束记录：目标、时间、设备或自动任务身份、安全目的摘要、内容摘要校验值或版本（适用时）、结果及必要错误类别。缺少结束证据时标为结果未确认，不推断成功；不把设备或自动任务猜成人工操作人。
- 自动化记录采用安全字段和脱敏摘要，不收集原始命令、完整环境、凭据或原始输出作为默认审计内容。输出、错误、部署日志和配置差异须先审查敏感字段，再按项目记录合同保存。
- 记录机制应保留原操作输出和退出状态；上传失败或暂缺结果须单独可见，不静默改变原操作结论。具体事件格式、排队、存储、保留期限和接收入口由实现项目维护，不在共享规则固定。
- 新增、变更或排查后，将有长期价值的当前用途、服务、端口、域名、故障结论及验证边界更新到项目指定的资产记录；连接资料变化同步到其受保护来源。一次性原始输出不堆入长期文档。

## 必须核对的场景

| 场景 | 可接受结果 |
|---|---|
| 未知程序或未知版本参数 | 仅查询元数据或已知 API；明确版本未确定 |
| 临时执行正常结束 | 业务验收与临时资源清理分别得到回读证据 |
| SSH 超时、失败或中断 | 核对远端执行边界；未知结果和清理失败明确保留 |
| 已确认遗留进程或新监听 | 精确清理并复查，不影响既有业务对象 |
| 部署或恢复命令成功 | 实际业务请求和数据通过项目验收后才声明恢复 |
| 状态采集失败或只有监听证据 | 不声称端口关闭或公网可用 |

修改探测或执行工具时，在隔离 fixture 中覆盖“收到未知参数就启动假服务”的程序，断言身份发现不会执行它；覆盖正常完成、本地 SSH 超时和中断后的远端清理，并确认原有业务监听保留。规则发布检查路由与链接，工具行为仍须用实际测试和远端证据验证。
