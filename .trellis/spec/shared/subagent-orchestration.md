# 子代理与外部 AI Worker 编排

本规范同时保存两类内容：可执行的协作合同，以及帮助主会话选模和判断现场的参考信息。参考信息可以形成强建议，但不自动变成模型资格、审批或完成门禁。

## 角色、执行器与职责

- `research`、`implement`、`check` 是稳定职责，不等于固定模型、provider 或进程类型。先按任务形态确定职责，再参考本文的模型与 effort 表选择当前可用候选。
- `research` 负责收集与比较证据；`implement` 负责在明确 ownership 内实现和自检；`check` 负责用独立问题设定核对受影响合同，并可直接修复发现的问题。
- 原生平台 subagent、Trellis Channel 外部 worker 和浏览器/桌面自动化是不同执行面。不得用一个执行面的启动回执、身份字段或并发状态推断另一个执行面已经运行或完成。
- 子代理正常可用的工具和推理能力不因角色名被削弱。项目因秘密、授权、成本或运行环境需要限制时，只在对应项目 owner 写明范围和理由。

## 派发与上下文交接

- 只把可独立推进的单元并行派发。提示中写明活动任务、目标、文件或模块 ownership、预期产物、必要验证、不得触碰的并行工作，以及已知外部副作用。
- Trellis 平台优先使用原生 `SubagentStart` 或等价机制注入上下文；不可用时，worker 自行读取活动任务的 `prd.md`、可选 `design.md` / `implement.md`、相关 spec 和需要的研究材料。
- `implement.jsonl`、`check.jsonl` 是精确交接时的可选清单；`routing.json` 也可以保存简短的共同路径、角色补充与理由。它们缺失不报错，不需要 digest、能力身份、运行状态或平行审批状态机。
- 上下文清单存在时按其路径读取正文，不把清单当正文摘要。内容与实际任务冲突、路径失效或 ownership 不清时，应回读真实文件并向主会话报告，不能从记忆猜测。
- 大上下文通过受保护文件、路径和索引交接，不展开到 Windows 进程命令行。临时材料限定到当前 worker，并覆盖正常退出、启动失败与取消时的清理。

## 能力事实与选择边界

- 模型、provider、effort、CLI flag 和实机版本由拥有这些事实的能力仓库、平台或当前探测结果提供。消费仓库与 Fleet 不读取或复制用户级登录、token、CC Switch 或 provider 配置。
- provider 实际报告的模型名和支持档位是事实；熟悉的别名、请求参数被 CLI 接受、界面标签或调用成功都不能单独证明实际模型与 effort。
- 如执行面能够观测身份，应区分 `requested` 与 `observed`。没有 provider/gateway 原始结果时把 observed 保持为 `unknown`；发生降级、重映射、换 provider 或串并行变化时如实说明即可。
- 上述身份信息用于解释一次运行，不是选择某模型前必须提交的证明、任务账本或完成条件。质量最终由代码、数据、文献与实际执行证据裁决。

## 跨项目模型与 effort 参考

下表是主会话的默认决策参考，不声明 provider 当前一定可用，也不是角色资格矩阵。项目领域约束、当前能力和实际结果可以改变选择；偏离时简要说明原因，不新增审批。

| 模型 ID | 请求 effort | 通常适合的任务 |
|---|---|---|
| `gpt-5.6-sol` | `medium` | 目标明确、约束完整、非探索性杂活、批量定位和整理 |
| `gpt-5.6-sol` | `high` | 有一定复杂度但范围明确；普通探索、跨文件分析 |
| `gpt-5.6-sol` | `xhigh` | 默认通用档；归类困难、需求有歧义或涉及多个系统 |
| `gpt-5.6-sol` | `max` | 高复杂度技术任务、关键逻辑和科学推理；领域规则禁止 Fable 时的强力替代 |
| `claude-opus-5` | `xhigh` | 能力定位在 Sol Medium 与 Sol High 之间且更接近 Sol High；约束明确的编码、前端、重构和普通文案，也适合并行拆分 |
| `claude-fable-5` | `xhigh` | 重要 UI/文案优化、复杂问题探索、独立复核和高价值验证 |
| `claude-fable-5` | `max` | Fable xhigh 已实际返回、且结果显示深度不足时再升级 |

- 模型 ID 与 effort 是独立字段；不得拼成伪模型 ID。调用面没有独立 effort 通道时，只传真实模型 ID，并把 effort 视为未应用或不可观测。
- 无法可靠归类时通常选择 `gpt-5.6-sol` + `xhigh`；约束完整的编码实现可优先 `claude-opus-5` + `xhigh`；普通探索可从 Sol high 开始。
- 高价值 `check` 优先考虑与实现者不同的模型家族，以增加独立视角；这是偏好而非强制。当前模型不可用、项目禁用、成本不合适或干净上下文已能提供独立性时，可以使用同一模型家族。
- Fable 通常先用 xhigh，只有实际结果不足时才考虑 max；不为这个升级建立证据文件、task ID、ledger 或失败关闭流程。
- 安全审查等安全主目标通常不交给 Fable；优先使用项目能力 owner 明确允许承担安全主目标的候选，当前表中的通用强力替代是 `gpt-5.6-sol` + `max`。这是能力边界建议，不要求普通任务先生成资格证明。
- 项目可以禁用某候选或收紧安全任务的选择，但必须由项目规则写明范围与理由，不能把临时不可用误写成全局能力结论。

## 并发与 provider 隔离

- 并发只用于 ownership 不重叠、确有并行收益的任务；上限不是目标数量。当前 Trellis Channel 的共享资源参考上限是同机 25 个 live worker，实际平台额度更低时采用较低值。
- 启动多个 worker 前查看平台提供的当前 live 状态；只有状态异常、锁错误或明显与进程不一致时，才进一步核对 supervisor/PID。不要把每次派发扩张成全仓审计、预约或账本流程。
- 并行 worker 不得反复切换同一个全局 active provider。存在真实的 per-process settings/env 隔离证据时可以跨 provider 并行；否则所有依赖同一个 CC Switch 等全局活动面板的 worker 串行，即使 provider ID 不同。
- 声明 per-process 隔离需要实际 provider 设置或 provider 环境证据；普通 `LANG`、测试变量等任意 env 不能证明隔离。不得读取、重写或切换用户级 Claude、Codex、CC Switch、provider 或认证配置。
- 每台设备按需探测实际 executable、CLI 版本和 `--model` / `--effort` 等支持。远端非登录 shell 的 `PATH` 可能不同，不能从本机可用推断远端可用。
- 检测到 `CLAUDE_CODE_EFFORT_LEVEL` 等环境值覆盖请求参数时明确警告并把 effort 记为不可确认；不能为通过检查而修改用户环境。

## 运行监督与中断恢复

- worker 不设跨项目硬执行 timeout。`idle_timeout` 或类似阈值只用于低频提醒和状态检查，不自动 interrupt 或 kill；启动握手、单次 RPC、锁、工具调用和单项测试可保留与操作相称的短技术超时。
- elapsed time、安静输出或慢推理都不是卡死证据。没有改变执行的新信息时，主会话优先等待或只读查看状态，不反复发送“继续”“尽快”。
- 启动调用返回 supervisor PID 或普通成功只说明调用被受理。需要依赖 worker 继续编排时，应等目标运行态或消息回执；完成仍要核对产物与检查。
- 中断前按现场核对：最近 durable progress、进程/日志活动、外部等待、最近检查点、可能发生的副作用和消息可达性。平台不可观测的项标为 `unknown`，不能猜成无活动。
- 用户取消、任务已由别处完成、明确失败或偏航、继续有危险、需要新授权或必须释放资源时可以中断。结构化监督报告不是中断前置门；核对深度与恢复价值相称。
- 意外中断、follow-up 无回执或状态不明时，先核对产物、checkpoint 与副作用。原 thread/session 可寻址、上下文可信、ownership 未变化且不会重复不明副作用时，优先恢复原会话。
- 只有原状态不可用、损坏、无法验证或替换的接管风险更低时才新开。接手提示应包含更换原因、已验证产物、剩余范围、ownership、已知副作用和停止条件，并确认旧代理不会同时修改同一对象。

### 现场判断示例

| 现场 | 建议动作 |
|---|---|
| worker 已完成约定范围与必要检查 | 立即交付，不为凑运行时长继续扫描 |
| 运行很久但进程/日志或外部等待仍健康 | 继续等待，必要时只发送一次新增信息 |
| 监督信息不完整或互相矛盾 | 标为 `unknown`，先只读核对，不仅凭安静中断 |
| idle warning 到点 | 检查一次状态，不自动 kill |
| 原 session 在意外中断后可验证恢复 | resume 原 thread/session，避免从头重复副作用 |
| 任务完成、明确失败/偏航或继续有危险 | 保留有价值产物后中断，并核对停止状态 |

## Trellis Channel 外部 worker 参考

- 一次性任务优先 print mode，prompt 经 stdin 或受保护文件传入，不拼接 shell 命令；连续上下文才使用 persistent mode 与明确 session identity。
- adapter 应处理进程启动、结构化输出、只告警监督、显式 cancel、退出码/stderr 分类和输出大小边界。真实调用可能产生费用或外部动作时，仍需当前任务授权。
- `--output-format json` / `stream-json` 可能抑制重映射提示，所以 argv、stdout 标签或“命令成功”只证明请求事实；实际身份优先看 provider 原始结果或适用的结构化 `modelUsage`。
- fake executable 与合成输入适合测试 adapter 行为；不要为了普通任务运行真实付费调用来证明编排流程本身。

## 独立复核与完成报告

- 普通小改允许作者自检。科学含义、跨模块合同、高影响验收或真实未决不确定性触发独立复核；独立指问题设定或上下文独立，不要求固定 implement → check 链，也不要求更换模型家族。
- reviewer 聚焦受影响合同、失败模式和证据，不默认扫描整个仓库。发现问题时可直接修复并重跑相关检查，直到本次范围可信或明确报告剩余阻塞。
- 每个代理交付实际修改、实际检查、未运行或失败项、外部副作用以及主会话需要整合的风险。不用模型身份、代理数量、运行时长或账本代替结果验证。
